# ADR 0003：动态敌机权重与更强的距离优先

- 状态：已采纳
- 日期：2026-10-25

## 背景

ADR 0001 的火控已经能计算提前量、按威胁排序并给多发武器分配目标，但有两个问题：

1. **敌机权重是静态的。** 只要敌机还在场上，类型权重就固定高于小行星。武器少时这是对的；
   武器多时，所有火力继续堆在敌机身上，漏过正在逼近的陨石。反过来，如果直接永久降低敌机
   权重，武器少时又会放任敌机输出。
2. **距离只是次级修正。** 现有 `proximity = 1 + 250/(距离+250)` 在 200 px 和 600 px 处只差
   约 17%，近处敌人的优先级不够明显。

需求是：

- 敌机保持最高优先级，但武器充足时不必全部打敌机；
- 敌机权重按“上次受伤到现在的时间”动态变化：长时间没受伤的敌机权重升高，刚受伤的敌机
  权重降低；
- 火力不足时自动把火力集中在敌机上，火力充足时自然分出一部分拦截陨石；
- 增加距离权重，更近的敌人优先度更高。

## 决策

### 1. 用生命值变化记录“上次受伤”

`FireControl.beginFrame` 增加 `nowSeconds` 参数（由 `WeaponSystem` 传入
`GameState.survivalTime`），并维护两张按实体区分的表：

- `lastHealth[entity]`：上一帧看到的生命值；
- `lastDamagedAt[entity]`：最近一次观察到生命值下降的时间。

每帧比较当前生命值和上一帧：

- 生命值下降 → `lastDamagedAt = now`；
- 生命值上升（治疗/对象池重置）→ 清除记录，视为从未受伤；
- 第一次看到该实体且已受伤 → 记为当前时间；满血首次出现 → 视为从未受伤。

这样不改 `Entity.takeDamage` 的所有调用点，也不会把闪避、护盾吸收、无敌等“没有掉血”的
事件误算成受伤。代价是同一帧内的伤害要下一帧才被观察到，最多延迟一帧，对索敌没有实际影响。

只对普通 `EnemyShip` 应用动态权重；Boss 保持原有高权重（Boss 是大血量单体目标，不应因为
刚被击中就把火力让给小行星）。跃迁、出生护盾等原有 `status` 降权继续叠加。

### 2. 敌机权重随受伤后的时间恢复

对普通敌机：

```
age = now - lastDamagedAt        // 从未受伤时视为无穷大
focus = 0.55 + 1.45 * (1 - exp(-age / 1.2))
threat = urgency * proximity * facing * typeWeight * status * focus
```

- 刚受伤时 `focus = 0.55`，敌机权重降到与近处小行星相当甚至更低，允许分火拦截陨石；
- 约 0.5 s 后恢复到高于小行星的水平；约 2.4 s 后接近上限 `2.0`；
- 从未受伤的敌机直接取上限，保持“敌机最高优先级”。

这里没有全局“武器数量”变量。武器多 → 敌机被命中的间隔短 → `age` 小 → 权重低 → 多余火力
转向陨石；武器少 → 命中间隔长 → 权重恢复 → 火力重新集中到敌机。这是需求描述的自然后果，
也比统计武器数量更贴近实际输出：武器在装填、打空、被 EMP 时不会虚报火力。

### 3. 增强距离权重

把距离因子从

```
1 + 250 / (距离 + 250)
```

改为

```
1 + 400 / (距离 + 200)
```

在 0 / 200 / 600 px 处分别约为 3.0 / 2.0 / 1.5；旧值约为 2.0 / 1.56 / 1.33。
同等条件下近处目标获得明显更高的分数，但预计撞击时间、朝向和类型仍然是乘数，不会让一个
静止的近距离小行星无条件压过正在高速撞来的敌机。

### 4. 与导弹齐射约束的关系

`requireEnemyFirst` 保留：存在可伤害敌机或 Boss 时，一轮导弹的第一发仍然锁定敌机，避免
整轮齐射转向陨石。第一发之后的槽位走动态权重，因此武器充足时同一轮里可以出现“部分打敌机、
部分打陨石”。

`sharePenalty` 不变：同一目标连续被选中时分数按 `1 + 已分配数 × 1.5` 衰减，保证多发武器
不会因为动态权重恢复而重新堆在同一条弹道上。

## 后果

- 火力不足时敌机权重会恢复到上限，玩家不会因为“刚打中一次”而放任敌机。
- 高射速/多武器时，敌机被持续命中，部分弹丸会转向近处陨石，减少漏怪。
- 刚被打中的敌机会有一个约 0.5 s 的低权重窗口。若实际手感过于频繁地分火，调高
  `focus` 下限或 `1.2 s` 恢复时间即可；这两个值集中在 `FireControl` 常量中。
- 动态权重依赖逐帧生命值比较，无法识别“同帧内先受伤后回满”的极端情况；当前游戏没有这种
  治疗路径，且只影响一帧的排序。
- 小行星不受“上次受伤”影响；它们仍然只按撞击时间、距离、类型和状态排序。
- 新增测试覆盖：近处敌人压过远处敌人、未受伤敌机压过小行星、刚受伤敌机暂时让位、恢复后
  重新压过，以及动态权重下多发武器仍能分散目标。

## 备选方案

- **全局按武器数量降低敌机权重**：需要统计射速、装填和命中率，且武器打空时权重仍然下降，
  会误判火力。否决。
- **每次 `takeDamage` 回调时间戳**：需要改所有伤害路径和实体池重置逻辑，侵入面大；逐帧
  生命值差分已经能得到同样的“上次实际掉血时间”。否决。
- **永久降低敌机类型权重**：武器少时会放任敌机，违背“缺少火力时集火敌机”。否决。
- **把距离改成平方反比**：近距离权重会过强，静止近处陨石容易压过高速来袭敌机；采用线性
  增强并在测试中约束。否决。
