# ADR 0001：武器火控系统（提前量、威胁排序与目标分配）

- 状态：已采纳
- 日期：2026-10-23

## 背景

游戏是单摇杆自动开火。此前的瞄准逻辑有三类问题：

1. **直线武器打当前位置**：Pulse Cannon 只朝最近目标的当前位置开火，目标横向移动时弹丸落在身后。
2. **导弹初速方向固定**：Homing Missiles / Autonomous Ace / Hunter-Killer 沿船头方向按扇形发射，只把目标当作制导目标；目标移动快时导弹需要先绕大弯，浪费寿命。
3. **导弹目标选择过于简单**：按距离排序后 `i % 目标数` 轮流分配，没有威胁评估；同一目标被分到多枚导弹时弹道几乎重合，视觉和实际命中都浪费。

需求是：给武器一套更合理、更精准的火控；初始 Pulse Cannon 必须计算提前量；第二艘船 Tracer 的导弹同样要提前量并改用比例制导或更优方案；导弹需要分析威胁、排序索敌，并协调同时攻击的目标分配；所有适用的武器都计算提前量。

## 决策

### 1. 拦截点解算

新增 `weapon/firecontrol/InterceptSolver`：假设目标匀速直线运动，解

```
|r + v·t| = s·t + R
```

其中 `r` 是相对位置，`v` 是目标速度，`s` 是弹速，`R` 是目标碰撞半径。平方后取最小正根，
得到提前量瞄准点和预计命中时间。无正根（目标比弹丸快且正在远离）时退回目标当前位置并标记
`valid = false`，由武器决定是否仍然开火。

### 2. 威胁评估与目标分配

新增 `weapon/firecontrol/FireControl`，每帧由 `WeaponSystem.beginFrame(targets, ship.position)`
重算一次威胁排序。威胁分不是单纯距离：

- 基础威胁：Boss > 高 tier 敌机；敌机按 tier 和射速加权；小行星按接触伤害加权。
- 距离越近、朝玩家接近速度越大，威胁越高。
- 跃迁中、出生护盾中、Boss 无敌/护盾中、碎片免疫中的目标降权，避免把火力浪费在暂时不可伤害的单位上。
- 生命值只做轻微影响，避免“残血目标自动变成最高威胁”。

多发武器通过 `allocate` 分配目标。选择分数为 `threat / (1 + 已分配数 × 1.5)`：

- 目标数量足够时，导弹会分散到不同威胁目标，不会全部扑向同一个。
- 高威胁目标仍然优先：Boss 的分数远高于杂兵，即使被分配多次也通常继续排在前列。
- 目标不足时按份额循环，每个目标最多分到约 `ceil(弹数 / 目标数)` 枚。
- 同一目标分到多枚弹丸时，瞄准点沿视线垂直方向按 `0, +1, -1, +2, -2…` 的间距错开；
  间距跟目标半径走并限制在 3–18 px，既形成不同弹道，又不会让弹丸偏出碰撞体。

单发武器使用 `aimAngle`，只取威胁最高的目标，不消耗分配额度；多目标瞬间武器使用
`selectTargets`，只做排序和分配，不生成瞄准点。

### 3. 武器接入

所有沿方向发射弹丸的武器都改为先取火控瞄准角，再叠加原有扇形/锥形/抖动：

- Pulse Cannon、Storm Cannon 的直线弹（Storm Cannon 本身是全向螺旋，只保留原弹道）
- Homing Missiles、Autonomous Ace、Hunter-Killer
- Scatter Shot、Leech Burst、Needle Gun、Siphon Needles
- Cluster Bomb、Flak Cannon、Flak Barrage、Railgun

Railgun 前向弹取最高威胁目标，后向弹取第二目标；没有第二目标时朝主目标反方向。

不计算提前量的武器是有意保留的：

- Nova Blast / Lingering Nova、Ion Orbiters / Frost Ring、Energy Saw / Warp Saw、
  Oblivion Beam：圆形/接触/持续伤害，没有“瞄准点”。
- Space Mines / Gambler's Mines：向后布置的固定雷区，靠敌人接近触发。
- Solar Storm / Phoenix Flare：瞬间在目标当前位置生效，飞行时间为 0，因此提前量为 0；
  但目标选择已改为威胁排序与分配。

敌机和舰队复用同一批武器类，因此它们的直线武器也会计算提前量；敌机仍只以玩家为目标。

### 4. 导弹制导

`Projectile.updateHoming` 从“朝目标当前位置转向”改为纯比例制导：

```
转向角速度 = N · Vc · λdot / Vm
```

`N = 3`，`Vc` 是接近速度，`λdot` 是视线角速度，`Vm` 是导弹速度。转向角速度仍受
`homingStrength` 上限约束。以下情况退化为追瞄：

- 接近速度低于 20 px/s（目标在远离或横向漂移）；
- 距离小于 100 px（末段避免比例制导抖动）。

发射时，导弹先按火控分配的瞄准点确定初速方向，再叠加原有发射扇形。这样导弹不需要先绕回
目标，比例制导只做修正。

## 后果

- 移动目标的命中率提高；Pulse Cannon 和导弹在横向移动目标上的表现变化最明显。
- 导弹火力会自然分散到多个威胁目标，减少重复弹道；Boss/精英仍然优先。
- 这是平衡性改动：实际 DPS 上升，尤其对高速目标。旋钮数值未改，后续如需要可用 Lab 调整。
- 火控是每帧一次 O(目标数) 排序加 O(弹数 × 目标数) 分配，目标规模下可忽略。
- 新增测试覆盖：拦截方程（静止/横向/追不上/带半径）、威胁排序、目标分散、弹道错开、
  比例制导命中、Pulse Cannon 提前量。

## 备选方案

- **纯追瞄**：实现简单，但横向目标会损失大量速度，导弹寿命不够。否决。
- **只给导弹加提前量**：Pulse Cannon 等直线武器仍然打空。否决。
- **严格轮流分配**：会为了“平均”把导弹分给无关的小行星，放弃高威胁目标。否决。
- **全局锁定/冷却窗口**：会让多武器重复攻击同一目标，且难以处理目标死亡。当前按帧分配
  已覆盖“同时开火”的协调需求，跨帧重复攻击同一目标是有意的补刀行为。
